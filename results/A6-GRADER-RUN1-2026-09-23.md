# Grader validation run 1 — hypothesis B is refuted, and inverted

`gemma4:latest` (8B), **one passage per call**, scored against the 440 human
grades. 437 of 440 graded; 4 unusable (one task died on HTTP 500 `prediction
aborted, token repeat limit reached` — model degeneration, not a transport fault).

## The two configurations, same model, same rubric, same passages

| | batch (the labels) | single (run 1) | human |
|---|---|---|---|
| graded 0 | 120 | **196** | 130 |
| graded 1 | 180 | 112 | 199 |
| graded 2 | 140 | 129 | 111 |
| **grade-0 gate** | 75.0% | **57.1% FAIL** | floor 90% |
| grade-2 gate | 90.0% | 92.2% | floor 80% |
| grade-1 exact | 62.8% | 74.1% | — |
| overall exact | 61.6% | 62.9% | — |

**False zeros — grader said 0, human said 1 or 2: 30 of 120 (25%) in batch,
84 of 196 (43%) alone.**

## ⚠⚠ Batch context was HELPING, not hurting

The hypothesis was that 15 visible siblings induce relative ranking, so
best-of-batch reads as an answer. The prediction was that isolation would fix the
grade-0 gate. **It did the opposite, and by a wide margin.**

Stripped of siblings the model rejects far more — 196 zeros against the human's
130 — and 43% of those rejections are passages the human found useful. The
siblings were supplying the scale: *useful compared to what.* Alone, the model
has no calibration for "does this help at all" and defaults to no.

⚠ **The other two numbers moved the right way**, which is the part worth keeping:
grade-1 exact rose 62.8% → 74.1% and the grade-2 gate rose 90.0% → 92.2%. In
isolation the model's POSITIVE calls get more trustworthy while its negative ones
collapse. Precision up, recall down — one dial, two directions.

⚠⚠ **Overall exact agreement barely moved: 61.6% → 62.9%.** A single headline
number hid a large, compensating redistribution across every cell. Read the gates.

## A trap this nearly walked into

The batch model graded **120** items 0 and the human graded **130** — a marginal
distribution that looks like close agreement. Only **90** of them are the same
items. **Matching counts is not matching decisions**, and any metric that reads
the margins rather than the pairs would have called the original labels fine.

## Ruling

Hypothesis B (batch context) is **dead**. The fix is not free and it is not the
prompt. Hypothesis A (capacity) is next: `gemma4:26b`, batch mode, everything
else held constant — same family, same host, same rubric, same passages, so size
is the only variable. Changing model AND provider together would confound it.

⚠ Production config stays **batch** regardless of what run 2 shows. Run 1
established that isolation costs more than it buys.
